# UI conventions

Applies to all frontend code in `frontend/src`. Coding agents and reviewers must follow it.

## Rules

1. **Use shadcn/ui components only.** When shadcn has a component for the job, use it rather than building your own: Button, Badge, Tabs, Collapsible/Accordion, ScrollArea, Tooltip, Separator, Switch/Toggle, Alert, Dialog, DropdownMenu, Table, Input, Select, Progress, Resizable, and so on.
   - Add missing components with the CLI: `cd frontend && npx shadcn@latest add <name>`.
   - The CLI currently writes files to a literal `@/` folder. Move them into `src/components/ui/` and keep the project's `cn` import (`from "cn"`).
   - Only customise a component through its `cva` variants, the way shadcn does it (for example, the `success`/`warning` variants on Badge).
2. **Use theme tokens only.** Allowed tokens include `bg-background`, `bg-card`, `bg-muted`, `bg-accent`, `bg-secondary`, `text-foreground`, `text-muted-foreground`, `border`, `ring`, `primary`, `destructive`, `chart-*` and `sidebar-*`. Opacity modifiers such as `bg-destructive/10` are fine.
3. **No hard-coded colours.** That means no `red-500`, `emerald-600`, `amber-*`, `text-white`, `bg-black` or hex/rgb values in components. The only exceptions are files generated by shadcn, such as the dialog overlay, and the channel/managed-adapter logos in `components/approvals/channel-logo.tsx`, which keep their official brand colours (including the owner-requested Google logos). Show integration logos only through `ChannelLogo`; generic HTTP and email icons use theme tokens.
4. **New semantic colours become CSS variables**, following shadcn's naming. Define them in `src/index.css` for both `:root` and `.dark`, and map them in `@theme inline` (as `--color-<name>`). Tokens already defined:

   | Token | Use |
   |---|---|
   | `success` / `success-foreground` | done, ok, passed |
   | `warning` / `warning-foreground` | running, pending, changed |
   | `info` / `info-foreground` | neutral highlights, such as JSON numbers |
   | `syntax-key` / `syntax-string` | JSON editor keys and strings. Numbers stay on `info`, booleans on `warning`, null and punctuation on `muted-foreground`. |
   | `destructive` | errors (shadcn built-in) |

5. **Node types each have a colour token** (addendum). Each type has three tokens: `--node-<type>` (accent), `--node-<type>-foreground` (text on a solid accent) and `--node-<type>-muted` (subtle background, the accent at 12% in light and 18% in dark). Types are `start`, `llm`, `tool`, `condition`, `end` and `code`. A canvas sticky uses `--node-note`, `--node-note-foreground` and `--node-note-muted` on the paper itself. It is not a graph node and does not go through `META`.
   - Example classes: `bg-node-llm-muted text-node-llm` (icon chip), `border-node-code/60` (Code node border). The canvas does not draw a left accent bar.
   - Use them in the palette, canvas node cards, the config header and trace timeline icons. They come from one map (`META` in `components/editor/meta.ts`), so don't copy the classes elsewhere.
   - Light values sit at about oklch L 0.5–0.64 so they contrast with white; dark values sit at about L 0.7–0.8, with dark foreground text.
   - Node-type colours mean *category*, not status. Status keeps using `success`/`warning`/`destructive`.

6. **Dark mode must work.** Use tokens only (never `dark:` colour overrides), and check that the screen looks right in both themes.

7. **Deletion requires confirmation**. Deleting, removing, revoking and unlinking require typing the item's name by default. Dataset row deletion uses a confirmation button without typed input. Dataset and column deletion still require the exact name.
   - Use the one shared `ConfirmDeleteDialog` (`components/confirm-delete-dialog.tsx`: shadcn AlertDialog + Input), usually through `useConfirmDelete().ask({ title, name, description, children, onConfirm })` (`components/use-confirm-delete.tsx`). Never `window.confirm`, and never a hand-made dialog.
   - When typing is required, the destructive button stays disabled until the text matches `name` exactly. Consequences such as dependents, reassignment or mode go in the `children` slot. Strings live in en + vi.
   - The confirmation is UI-only, as on GitHub. The API stays a plain `DELETE` with no `confirm_name`, so API clients and scripts are unaffected.

8. **Attention icons use a semantic colour**. Every warning or alert icon shows how serious it is:
   - **Danger or irreversible** (errors, failed runs, validation errors, delete confirmations): `text-destructive`. Use `<Alert variant="destructive">`, or put `TriangleAlert className="text-destructive"` in the `ConfirmDeleteDialog` title.
   - **Non-destructive caution** (timeouts, cancelled runs, missing connections, admin-only notices, policy blocks, transfer issues, changed subgraphs, session-expired notice, expired approvals): the `--warning` token. Use `<Alert variant="warning">`, whose icon becomes `text-warning` with a `border-warning/50` border while the text stays neutral, or put `text-warning` on a standalone icon.
   - Informational or success notices keep the default variant.
   - `--warning` / `--warning-foreground` are shadcn-style CSS variables (light and dark in `index.css`), registered as `--color-warning*` in `@theme`. Never use raw palette colours.

9. **Template fields use `TemplateEditor`**. Any node field that the backend renders with `{{state.field}}` (`engine/templating.py`) uses `components/template-editor.tsx`, not an Input or Textarea. It shows references as tags (path and filters included), marks fields missing from the state schema and unknown filters, suggests fields after `{{` and filters after `|`, opens a tag as text on double-click, and has an insert-field menu. Pass `readOnly` for viewers: CodeMirror ignores a disabled `fieldset`.

10. **Vietnamese strings follow the glossary** in [`frontend/src/locales/vi-glossary.md`](../frontend/src/locales/vi-glossary.md). `frontend/src/locales/vi.json`, `README.vi.md` and `handbook/docs/vi` use its terms, its form of address, its tone-mark style and its rule for the polite "please" (error messages only). Buttons are short imperatives. `src/lib/__tests__/locales.test.ts` checks key and placeholder parity, the banned terms, and that every vi string left identical to en is on its reviewed allowlist.

11. **Alignment & sizing**. Controls that share a row line up by construction, not by hand.
    - **One size variant per row.** Button, Input, SelectTrigger, TabsList and Toggle in one row use the same shadcn size: the default size is 32px (`h-8`) for all of them (Button `default`/`icon`, Input, SelectTrigger `default`, TabsList), `sm` is 28px (Button `sm`/`icon-sm`, SelectTrigger `sm`, TabsList `sm`) and `xs` is 24px (Button `xs`/`icon-xs`). Inputs only come in 32px, so a row with an Input uses the default size.
    - **Never hand-set `h-*`, `py-*`, `leading-*` or `text-[…]` on a shadcn control.** Use the `size` prop, or add a `cva` variant to the ui component (as Badge `size="sm"` and TabsList `size="sm"` do). Width, margin and layout classes (`w-*`, `flex-1`, `ml-auto`, `min-w-0`) are fine.
    - **Icons** inside a control take their size from the component's own `[&_svg]` rule (`size-4`, smaller in `xs`/`sm`). Don't add `size-*` to an icon inside a Button or Badge. Icon + text is `items-center`, which every control already sets.
    - **Mixed fonts or sizes on one line** (a mono id next to a time, a number next to a label) align on the text baseline: wrap them in `inline-flex items-baseline`, give them one size and line height, and use `tabular-nums` for numbers. Never `leading-none` to force them together: equal box centres do not give equal baselines.
    - **Toolbars** are `flex items-center gap-2` with a fixed row height (`h-11`, `h-14`) instead of vertical padding, so a taller or shorter control cannot shift the row.
    - Components whose size is their content (Skeleton, ScrollArea, Separator, ResizablePanel) are sized with classes as shadcn shows; layout containers that need an exception (an empty-state TableCell, a flush Card) carry `/* ui-class-ok: <reason> */` on the element.
    - Checked by `npm run lint` (`scripts/check-ui-classes.mjs`, also on CI) and by `e2e/alignment.spec.ts` (`expectRowAligned`, `expectBaselineAligned` in `e2e/helpers/alignment.ts`, light and dark, en and vi).

    | Don't | Do |
    |---|---|
    | `<Button size="sm" className="h-6 px-2 text-xs">` | `<Button size="xs">` |
    | `<Input className="h-8" />` next to `<Button size="sm">` (32px vs 28px) | `<Input />` next to `<Button>` (both 32px) |
    | `<SelectTrigger size="sm" className="h-7">` | `<SelectTrigger size="sm">` |
    | `<Badge className="h-4 px-1 text-[10px]">` | `<Badge size="sm">` (add the variant in `ui/badge.tsx`) |
    | `<TabsList className="h-7"><TabsTrigger className="h-5 text-xs">` | `<TabsList size="sm"><TabsTrigger>` |
    | `<Button><Play className="size-3.5" />Run</Button>` | `<Button><Play />Run</Button>` |
    | `<span className="leading-none">21:07</span><span className="font-mono text-xs leading-none">2959fe</span>` | `<span className="inline-flex items-baseline gap-1.5 text-xs"><span className="tabular-nums">21:07</span><span className="font-mono tabular-nums">2959fe</span></span>` |
    | `<div className="flex gap-3 py-1.5">` toolbar | `<div className="flex h-11 items-center gap-2">` |

12. **Node Config uses the same tabs for every node** (owner amendment). The owner requested **General · Settings · Data · Execution** (the vi labels are in the glossary) at the top on 2026-11-04. `components/editor/editor-config.tsx` puts the node's icon, id and Label in General. The tab selection is kept between nodes and unused tabs remain disabled.
    - Palette/State schema and Config headers use the shared shadcn Tabs `panel` variant: rectangular tabs attached to the panel edge, no floating pill group, existing theme tokens and keyboard navigation.
    - **General**: the node identity, description, Label and incoming/outgoing connections; initially selected, available for every graph node. Connection links navigate to the existing neighbour, rather than duplicating its editable settings (owner follow-up).
    - **Settings**: what the node does: credential, model, prompts, tools, mode, code, approvers and deadline, a condition's default label.
    - **Data**: every picker of a state field: output field, steps and history fields, a loop's items/item/index fields, the field a Condition branches on, a Decision's answer fields, and the input fields switch list.
    - **Execution**: how the node runs: retry, wait, timeout, cache TTL, and limits (Agent max rounds, For each max items).
    - A tab the node does not use stays in its place, disabled; never hide it or add a node-specific tab. The chosen tab is kept while another node is selected.
    - A tab whose content needs attention (a required output field, an Agent without tools) shows a `bg-destructive` dot.
    - A new node type puts each field in the tab this rule names. A settings component that would span tabs exports one part per tab (as `AgentSettings` / `AgentData` / `AgentExecution`).

13. **Dialog scrolling and state-field quick actions** (owner follow-up).
    - Long dialogs use a viewport-bounded flex `DialogContent`, fixed `DialogHeader` / `DialogFooter` and a scrollable `DialogBody` (or the existing equivalent `min-h-0 flex-1` ScrollArea). The dialog shell must not scroll its header or actions away. Reserve space for focus rings in the body.
    - Empty Select menus must visibly explain that there are no options; loading and lookup errors must not masquerade as an empty result. The Studio SelectContent provides the shared empty state.
    - State pickers use the shared StateFieldAction/StateFieldPicker where in-place creation is available. Creation is explicit, typed and undoable in the draft, not an automatic schema change. Saved-workflow settings must clearly disclose and request the workflow save before referencing new draft fields.
    - Panel tabs have no box shadow; retain a visible keyboard outline and an active-tab border. Align Alert icons by grid layout, not per-call-site translation offsets.

## Review checklist

- [ ] No custom widget where shadcn has a component.
- [ ] This command finds no hard-coded colours:
  `rg -n "(text|bg|border|ring)-(red|emerald|green|amber|yellow|orange|sky|blue|violet|purple|teal|zinc|gray|slate)-[0-9]|text-white|bg-white" frontend/src --glob '!components/ui/**'`
- [ ] This command finds no hex colours outside the channel logos:
  `rg -n "#[0-9a-fA-F]{3,8}\b" frontend/src --glob '*.tsx' --glob '!**/components/ui/**' --glob '!**/approvals/channel-logo.tsx'`
- [ ] Every new delete/remove/revoke/unlink goes through `ConfirmDeleteDialog`. Type the name except for dataset row deletion. Confirmation is UI-only.
- [ ] Node fields rendered as `{{state.field}}` templates use `TemplateEditor`.
- [ ] Warning/alert icons: destructive for danger, `variant="warning"` / `text-warning` for cautions; none left in the neutral default colour.
- [ ] New vi strings follow the glossary (rule 10) and `npm test` passes the locale checks.
- [ ] Controls in one row use one size variant, with no hand-set `h-*`/`py-*`/`leading-*`/`text-[…]` (`npm run lint` passes; any `ui-class-ok:` opt-out gives a reason), and `e2e/alignment.spec.ts` covers new toolbars.
- [ ] New node fields sit in the Config tab rule 12 names (Settings, Data or Execution).
- [ ] Screenshots are taken in both light and dark mode for UI changes.
