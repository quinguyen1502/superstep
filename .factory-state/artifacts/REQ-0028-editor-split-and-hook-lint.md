## Summary

Split `frontend/src/pages/Editor.tsx` into smaller modules and clear the React hook oxlint warnings, without changing behaviour.

## Problem Or Opportunity

- `Editor.tsx` is 755 lines (64 KB). `Studio` alone is about 500 lines with 27 `useState` calls, mixing loading, saving, running, the header, the palette, the config panel, and the run panel. Every editor task edits this one file.
- `npx oxlint` reports 46 warnings: `react(refs)` (12, mostly `lib/use-graph-history.ts`), `react(set-state-in-effect)` (13), `react-hooks(exhaustive-deps)` (12), `react(only-export-components)` (9). Most come from the same "load on open" effect pattern repeated in dialogs and settings sections.

## Scope

### In Scope

- Move the header, the left panel (palette + state schema), the config panel, and the run panel out of `Studio` into components under `frontend/src/components/editor/`
- Move run and save logic into hooks (`use-editor-run`, `use-editor-save` or similar), keeping one source of truth for graph state
- One shared data-loading hook for "fetch when open / when id changes" and use it in the dialogs and settings sections that warn
- Fix or explicitly justify every remaining oxlint warning; `components/ui/*` files generated by shadcn may keep `only-export-components` with an inline disable comment

### Out Of Scope

- New features, visual changes, or new API routes
- Changing the shadcn component sources beyond the lint comment

## Stakeholders Or Users

- Developers working on the editor

## Desired Behavior

- The editor looks and behaves the same: every existing Playwright spec passes unchanged except for imports.
- `Editor.tsx` is the page shell only (well under 250 lines). No new file over 300 lines.
- `npx oxlint` exits with 0 warnings, or each remaining one has an inline reason.

## Business Rules

- UI rules from `docs/ui-conventions.md` (DEC-0008) still apply. Strings stay in both locale files.

## Constraints

- Start after PR #41 (TASK-0038, panel layout in `Editor.tsx`) and PR #42 (TASK-0039, header grid and lazy routes) are merged into `develop`, because both change `Editor.tsx`.

## Acceptance Criteria

- Full Playwright suite: no new failures compared with `develop` at the start of the task.
- `npx tsc -b`, `npx vitest run`, `npx vite build` pass.
- `npx oxlint`: 0 warnings, or every remaining warning has an inline disable with a reason.
- `wc -l frontend/src/pages/Editor.tsx` is below 250.

## Edge Cases

- Keyboard shortcuts, undo history, clipboard, and command-palette registrations keep working after the move (their specs cover them).
