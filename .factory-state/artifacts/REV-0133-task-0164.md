## Findings

### Blocking

### Non-Blocking

- "Save as test case" is wired to `POST /api/workflows/{wid}/tests/from-run/{rid}` and `TestCaseDialog`. The button is disabled when `run_exists` is false, and the API test deletes the run and reads `run_exists: false`. Nobody clicked the button in the studio, so the dialog opening is unread.
- A builder rating their own chat is covered by the studio API test and by the same `ChatRatingBar` the public e2e clicks. The studio screen itself was not clicked.
- The e2e opens the thumbs-down filter and checks that the totals line is visible. It does not assert that the visitor list shrinks. `test_builders_see_the_mark_the_filter_and_the_totals` checks that the filtered API returns only the down chat.

## Standards And Architecture Alignment

- `canEdit` is `studio.edit && !studio.source`, the same gate as save-as-test on a run. Visitor chats pass `onSaveTest` and do not pass `onRate`.
- The share is `down / (up + down)`, rounded, with an em dash at zero (`downShare`). Totals sit on their own line so the compact toolbar is not crushed.
- Turning the filter on while the builder's own chat is open (`vsid` null) does not jump to a visitor chat.

## Design Alignment

Matches DEC-0070: read-only marks on visitor chats, filter, 7- and 30-day totals, and save-as-test only on a rated answer whose run still exists.
