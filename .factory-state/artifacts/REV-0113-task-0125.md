### Non-Blocking

- **The TypeScript file follows the Python file step for step.** It uses the same entry, model, tool and end steps
  (DEC-0063) and the same `agent_<name>` state field. `same_run` in the tests compares the TypeScript run with the
  studio's run for an approved call, a rejected call with a reason, a knowledge base tool and an agent inside a
  subgraph.
- **The tool step re-runs from the top on resume.** The step takes the first pending call before `interrupt()`.
  LangGraph re-runs the step with the state from before the step, so the call is taken again and is not lost. The
  generated comment says so.
- **No secret reaches the file.**
  - HTTP tools write the URL, method and body template only. Credentials stay on the server.
  - MCP and knowledge base tools call the existing `callMcpTool` / `retrieve` stubs by tool name, with no server or
    knowledge base id.
  - `test_agent_nodes_are_exported` checks that the `SECRET` value is absent.
- **Built-in tools are stubs that throw.** The model is still told about them, and a call returns "The tool
  failed: …" to the model, as a failing tool does in the studio. This matches the Tool node's stubs.
- **Not checked against a real model.** The `LLM_PROVIDER` path (`initChatModel` + `bindTools`) passes `deno check`
  against LangChain.js, but no run used a real provider. The mock path is the one the tests run.
