## Findings

### Non-Blocking

- **One choke point.** Every stored write of a workflow goes through `WorkflowService._write`, so these paths are all covered by one check:
  - save and create;
  - template use (through `save`);
  - version restore;
  - ownership transfer (`write_as`);
  - repo-import finalize.
  - A future write path is covered by default, because `before` is read from the database when the caller does not pass it.
- **What counts as writing code.** The check compares each Tool node in Code mode by id with its stored source. These stay allowed:
  - moving or renaming the node, or changing its other fields;
  - deleting the node;
  - switching it to another mode.
  - Copying a whole workflow (`duplicate`) is allowed by DEC-0041, because the copy holds only code that already exists. Template use is checked, because the template's code is new to that workflow.
- **Template import.** Importing a template file with Code nodes is checked when the template is stored. Saving a template from a workflow (`save_from_workflow`) is not checked, because it only copies code the user can already see.
- **Imported repo nodes.** Nodes of type `code` from repo import are a different node type and are not affected.
- **No new query on save.** `save` already loads the stored graph and passes it in. The extra repository read happens only for in-place writes that do not pass `before`.
- **`self.access` is None.** In owner-only setups (some unit tests) the check is skipped, the same as the other permission checks in this service.
