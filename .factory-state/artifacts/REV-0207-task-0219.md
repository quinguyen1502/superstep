## Standards And Architecture Alignment

- en/vi have the same page paths and heading structures. Shared snippet files prevent signing code diverging between languages. Navigation links both languages to the API, auth and compatibility pages.
- The route table covers all 11 public HTTP operations, including turns, attachments and ratings, with byte-download exceptions to the envelope explained. Legacy aliases are distinguished from the old untyped socket.
- Token examples pin HS256, set kid/iss/aud/sub/iat/exp, use the displayed secret's UTF-8 bytes, and issue a ten-minute lifetime. No actual key or token is committed. Secret storage, authenticated identity derivation, origins, cross-origin no-credentials policy, clock leeway and immediate next-verification revocation match the code.
- Scope of user history across rotation keys, untrusted identity/meta and the required object state field `chat` are explicit. Human answers, the possible absence of `turn`, resetting seq, delayed persistence and duplicate-send risk are documented accurately.
- The compatibility page states the accepted additive-only v1 policy and minimum 12 months after v2, while explicitly stating that no v2 sunset or Deprecation/Sunset response headers are currently enabled. Approval statuses of REQ/DEC artifacts are preserved.
- No new application UI, delete interaction, backend layer, catalogue entry, database migration or dependency.
