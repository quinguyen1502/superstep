## Findings

### Blocking

- None.

### Non-Blocking

- `PatService.user_for_token` repeats `AuthService._from_pat` and nothing calls it. Requests go through `_from_pat`.
- `POST /api/auth/cli/devices` and the approve route have no rate limit. The user code is 8 hex characters. Guessing one does not issue the victim's token: approve binds the token to the account that is signed in on the page, and only the CLI that holds the device code can poll it.
- If `GET /api/me` fails after the CLI has taken the secret, `cli.json` is not written and that server token stays active until it is revoked by name in Settings.
- The active-name check and the insert use two sessions. Two concurrent creates of the same name can both succeed.
- `cli_devices.secret` holds the new token until the first poll. DEC-0071 asks for that. A database copy in that window contains the secret.
- Settings and `/cli/authorize` were not opened in a browser. The API tests call the routes with a Bearer token. The page uses `api()`, which sends the session cookie and `X-Requested-With`.
- Create and revoke do not write an audit event.

## Design Alignment

- DEC-0071 decision 1: `SUPERSTEP_TOKEN` and `SUPERSTEP_URL` win over `~/.superstep/cli.json`. `--url` wins over the environment. `login` stores `url`, `token` and `account` and sets the file to mode `0600`. `logout` removes `token` and `account` and leaves `lang` and `current`. The token is not printed.
- DEC-0071 decision 2: only the SHA-256 is stored on `personal_access_tokens`. The secret is `pat_` plus `token_urlsafe(24)` and is returned once. Active names are unique per user. A `pat_` bearer and `/ws/run?token=` resolve to that user. A password change does not revoke the token. A JWT still uses the old path.
- DEC-0071 decision 3: the device codes are stored as hashes. The poll returns the secret once. The approve page does not call the server until Approve or Deny. Settings lists the prefix and revokes by the typed name.
- The approve page shows the signed-in email, the code, and the token name.
