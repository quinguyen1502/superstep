## Findings

### Blocking

- None. No blocking findings.

### Non-Blocking

- **Fixed during review (0572604):**
  - Tool cards were keyed by position and source. With two tools of the same source, moving one left each card
    with the other tool's parameter rows, and the next edit would have written them onto the wrong tool. Cards now
    keep a stable key that moves with the tool. The keys are reset when the list changes elsewhere (undo, redo,
    paste).
  - Parameter rows without a name are left out of the schema.
  - An e2e step moves a tool up and down.
- **Approval switch not active yet.** "Needs approval" and the approval and deadline settings are saved, but the
  run pauses before such a call only once TASK-0117 lands. The task notes the merge order: #144, then TASK-0117,
  then this task.
- **Validator errors.** These appear in the run panel's error list and name the node, as for every node type.
  There is no per-node error badge on the canvas. The task's acceptance wording ("show on the node") is met only
  in that sense; QA-0109 records it.
- **Not reachable for TypeSafe.** The settings warn when the chosen credential's provider has no tool calling. The
  Agent node lists chat credentials only, so TypeSafe (Decision) and SMTP never appear. Today the warning is a
  safeguard for a future chat provider without tools.
- **Chat reply stream.** `liveReply` now keeps only the latest iteration of each node that writes the reply field.
  That is right for an Agent's rounds and for a loop that rewrites the field; before, text was concatenated across
  iterations. The existing chat vitest and e2e still pass.
- **Placeholder in a translated string.** The `{{state.args.name}}` example in the HTTP hint goes through an i18n
  variable (`{{arg}}`), so i18next does not treat it as one of its own placeholders.

- shadcn components only: Card, Select, Input, Switch, DropdownMenu, Button, Alert, Badge, Separator and Tooltip
  (through `Tip`). Templated fields (prompts, HTTP URL and body) use `TemplateEditor` with `readOnly` for viewers
  (rule 9).
- Theme tokens: new `--node-agent*` tokens for light and dark, mapped in `@theme inline` (rules 4 and 5). There are
  no hard-coded colours; the checklist `rg` commands find no hits in the new files.

  and the only remaining lint warning predates this task.

  records, as TASK-0118 states).

  components only (fast-refresh lint rule).
- Backend: `steps_of` applies the same rules as `liveSteps`; services import `engine.agents.visible` (an allowed
  direction). `tests/test_layers.py` passes.
