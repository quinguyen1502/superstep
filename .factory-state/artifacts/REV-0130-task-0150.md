## Non-Blocking

- `instance.json` is written before `docker pull`, `compose up`, and the health wait. If one of those fails, a second `install` sees the record and refuses, and it does not rewrite `.env`. The operator has to remove the directory by hand. The acceptance checks cover a missing Docker engine, which still exits before any file is written.
- The memory warning uses total RAM (`SC_PHYS_PAGES`), not free memory. A large host that is almost full of other processes does not warn. The threshold in DEC-0068 is still applied to the number the CLI reads.
- `error.docker_failed` and `error.health` can echo a URL or Docker's stderr. A password placed in `--url` would show up there, the same note as REV-0129.

## Standards And Architecture Alignment

- DEC-0068 decision 3: directory `~/.superstep/instances/<name>/` or `--dir`, mode `0700`, `.env` and `instance.json` mode `0600`, `remote` stays `null`. A second install refuses.
- Decision 4: `single` is the default. Images are pinned to the CLI version. `full` uses `pgvector/pgvector:pg17`, `redis:7-alpine`, `superstep-api`, and `superstep-web`. `--sandbox` adds `superstep-sandbox` and is rejected on `single`. There is no `build:` path. Volume names are `<name>_data` or `<name>_pgdata`, `<name>_redisdata`, `<name>_apidata`.
- Decision 5: the CLI shells out to `docker` and `docker compose`. Tests use a fake. Missing engine or Compose v2 exits before files are written. `--images` loads and does not pull. Low memory and low disk warn and do not block. A taken port names the process. `--yes` without `--port` fails when the default port is taken.
- Decision 6: generated secrets stay in `.env`. They are not printed. The admin password is printed once and is not stored in `instance.json`.
- The web image's default upstream is `api:8000` (`frontend/Dockerfile`), which matches the generated service name.
- No new dependency and no API change.
