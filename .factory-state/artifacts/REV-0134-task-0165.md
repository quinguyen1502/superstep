### Non-Blocking

- Two jobs that both run before `feedback_id` is stored can create two LangSmith feedbacks. DEC-0070 already records that. The test holds the worker's `on_rating` and calls the real method itself, so the race is not executed.
- Deleting a rating does not enqueue a job and does not retract the LangSmith feedback. That is the decision.

## Standards And Architecture Alignment

- The worker handles `kind: chat_rating` before the generic run path, which reads `run_id` and would otherwise fail.
- `on_rating` returns when the key is missing, tracing is off, or `trace_root` is empty. It does not read the studio evals switch. Errors are logged and not raised, same as `on_suite_done`.
- The run id is `run_id_of(trace_root)`. The first call is `create_feedback` with key `user_rating`. A stored id takes `update_feedback`.

## Design Alignment

Matches DEC-0070: one feedback object, score 1 or 0, comment or none, HTTP returns before the LangSmith call (`jobs.enqueue` after the row is saved).
