## Findings

### Blocking

- None. No blocking findings.

### Non-Blocking

- **The comment is a text reply.** The answer shape stays as it is (Approve, Reject or a text reply, the same for the
  inbox, the run panel and the channels), so no schema change is needed. `approved` runs the call; `rejected` or any
  other text rejects it, and a text reply becomes the comment ("Rejected by a reviewer: <text>"). The prompt says so in
  en and vi. The Reject button does not send the typed text; TASK-0120 should document "type the reason and send it".
- **The rejected status in the trace.** `agent_tool` steps can now have status `rejected` and an `approval` field. The
  trace summary in TASK-0118 (#145) labels statuses through `trace.agent.status.<status>`, so #145 needs a
  `rejected` label (en, vi). Done on the #145 branch in dcf10fc.
- **Chat approvals go to a reviewer.** In a chat-enabled workflow, an Agent tool approval is answered in the
  Approvals inbox, never by the person chatting, whatever a Human node's `answered_by` default is. This follows the
  purpose of the approval (someone other than the requester approves the agent's action) and is recorded in the task
  log.
- **Invalid calls do not ask.** A call to an unknown tool or with invalid arguments fails as before without a wait,
  so an approver never sees a call that cannot run.
- **Test case answers.** Answers for an Agent node's approvals are keyed by the Agent node's id (`ag`), as the task
  says; the `no_answer` detail names the waiting step (`ag/__tool`). The Tests panel's answer editor lists Human
  nodes only; TASK-0119 adds the Agent node there with the template.
- **Template sanitising (outside this task).** `templates.sanitize` blanks resource ids at the top level of node data.
  The Agent node's `server_id` and `knowledge_base_id` live inside `tools`, so a saved template keeps them. They are ids,
  not secrets, and the receiving user cannot use another user's resources, but TASK-0119 (templates) should blank them.
- **Older expansions.** A run expanded before this change has no `agent_label` on its steps; the prompt then uses the
  Agent node's id. Only unreleased branches are affected.
