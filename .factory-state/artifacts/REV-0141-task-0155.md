### Non-Blocking

- `docker compose` is a local client. Deploy writes the remote directory first, then runs compose against a temporary local cache so the client can read `compose.yml` and `.env`. `DOCKER_HOST` selects the remote daemon. The cache is removed when the command returns. Secrets from `.env` exist on the operator machine for that interval. `instance.json` `dir` and the timer script use the remote path.
- Deploy does not probe the remote host port. A port that is already taken fails when `compose up` runs.
- SSH uses `BatchMode=yes` and `StrictHostKeyChecking=accept-new`. A new host key is stored. A changed host key still fails. BatchMode cannot show a prompt.
- A second deploy whose CLI version equals the remote version follows `upgrade`: it does not pull, back up, or generate secrets. A newer CLI version runs backup, pull or `--images` load, and restart. Deploy does not print the changelog range that `superstep upgrade` prints.
- The timer is the TASK-0152 shell script, copied over SSH. It calls `docker` on the remote host and checks the volume names. The SQLite path runs `python -c` inside the container. The script has no `pip` or `uv`. Enabling the timer uses remote `systemctl --user` or `crontab`. If neither works, the instance is already installed and the command exits non-zero.
- Shell completion lists the top-level command `deploy`. It does not list the flags.

## Standards And Architecture Alignment

- DEC-0068 decision 5: the instance directory is created on the Docker host at `~/.superstep/instances/<name>/`, or at `--dir`. `instance.json` `remote` is the `ssh://` URL. Engine calls set `DOCKER_HOST`. The remote host is not given Python, the CLI, or a git checkout.
- The install and upgrade sequences are the existing helpers (`_compose`, `_image_list`, `upgrade_instance`, `_shell`). Deploy does not add a second compose generator or a second backup script.
- Secrets are written only into the remote `.env` with mode `0600`. The one-time admin password is printed once, the same exception `install` already uses. It is not written into `instance.json`.
- CLI errors stay in the catalogs. No new code in `core/errors.py`.

## Design Alignment

No design artifact. Help text, JSON, and the two languages follow REQ-0079. `deploy` has an example. The new en and vi keys match and the sentences differ. Human text goes to stderr. `--json` writes one object on stdout. An install object includes `admin_password` once. An upgrade object has no `admin_password` key.
