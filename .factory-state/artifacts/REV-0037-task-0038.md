### Non-Blocking

- Sizes are saved only after a user drag (`isUserInteraction`). A window resize or the minimums squeezing a panel does not overwrite the stored sizes on its own. The next drag saves the sizes the panels have at that moment, which can be the squeezed size of the other panels on a small window.
- The side panels and the run panel use `preserve-pixel-size`, so a window resize changes the canvas, not the panels. This matches "the canvas takes the space that is left".
- Double-click on a handle is disabled (`disableDoubleClick`), because restoring the default is out of scope and the library would restore the stored size instead.
- The handles are the shadcn default: a 1px line with a 4px hit area, focusable, with arrow-key resizing from the library. No visible grip (`withHandle`) was added.
- The config panel content was pinned to `w-[318px]` and the read-only source to `w-[286px]`. Both are now fluid, so the extra width is usable. A narrow config panel (260px) keeps the fields inside the panel.
- `npx shadcn add` also let npm rewrite unrelated lockfile fields (`libc`, `dev`) on macOS. The committed lockfile keeps the `develop` content plus the one new package entry, so `npm ci` on Linux is unchanged.

## Standards And Architecture Alignment

- shadcn Resizable from the CLI, moved into `src/components/ui/` with the `cn` import. No hand-rolled drag layer.
- No hard-coded colours (the ui-conventions checklist command finds nothing). The handle uses `bg-border` and `ring`.
- The three aria labels are in `en.json` and `vi.json` with the same keys.
- No backend change, no API route, no error code. Sizes are not part of the workflow JSON.

## Design Alignment

- Header stays a fixed `h-14` (56px) outside the resizable groups.
- One layout component serves the editor and the loading skeleton, so they read the same stored sizes.
- The handles sit on the panel borders. A node drag on the canvas does not reach a handle.
