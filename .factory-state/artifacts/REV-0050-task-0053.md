### Non-Blocking

- **Isolation.**
  - The server only calls `ast.parse` on user code; a test checks that a source calling `os.system` is not run by validation.
  - The container gets `--network none`, `--read-only`, `--cap-drop ALL`, `no-new-privileges`, limits on pids, memory and CPU, no `-v`, and no `--env-file`.
  - Its environment is three fixed variables. A Docker test sets `JWT_SECRET` on the server and shows that the container sees no `JWT*`, `STUDIO*` or `DATABASE*` variable, no network and no server checkout.
- **Runner delivery.**
  - The runner is passed as `python -I -c <source>`, so no host directory is mounted and the stock `python:3.12-slim` would also work.
  - This avoids the `STUDIO_IMPORT_HOST_DIR` path translation that imports need under Compose.
  - The runner's source shows in `ps` on the host; it holds nothing secret.
- **Result channel.**
  - The result is the last stdout line.
  - Code that writes to `sys.__stdout__` or fd 1 could print its own result line, but it can only fake its own node's value, which it can already return.
  - Ordinary `print()` goes to the captured buffer.
- **Time limit.**
  - The node's timeout (REQ-0019 thread) and the container's limit use the same number, capped by `STUDIO_CODE_MAX_SECONDS`, so a timed-out attempt does not leave a container running.
  - Docker start-up counts toward the limit (about 0.25 s here).
- **Cancel.**
  - `Ports.cancelled` is `cancel.is_set() or bus.is_cancelled(rid)`, and it is polled every 0.25 s while a call runs.
  - With the Redis bus this is one Redis read per poll per running Code node, which is acceptable.
  - A cancel still waits for at most one poll interval plus `docker kill`.
- **Concurrency.**
  - A per-process semaphore (`STUDIO_CODE_CONCURRENCY`, 4) bounds containers.
  - Waiting for a slot counts toward the call's time limit and ends as `CODE_TIMEOUT`.
- **Validation cost.**
  - Any workflow with a Code node runs `docker image inspect` during validation, on save and on run.
  - The result is cached for 30 s per image and per process, and an "image missing" result is dropped as soon as a run sees the image.
- **Error text.** `errors[0]` of a run error event reads `CodeFailure: Code node c raised …`, because `safe_error` prefixes the exception type, the same as other `AppError` codes. The UI translates by `code`.
- **Not in this task:**
  - who may write code (`code.write`, TASK-0054);
  - the editor and Test with sample state (TASK-0055);
  - the subprocess runtime and its warnings (TASK-0056).
  - Until TASK-0055 the Code mode is reachable only through the API or imported JSON, and only when an admin turns it on.
