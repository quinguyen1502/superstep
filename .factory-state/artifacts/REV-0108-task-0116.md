### Non-Blocking

- **Fixed during review (de0a7f5):**
  - With no body template, an HTTP tool's JSON body was built from the model's arguments and then rendered as a
    template. An argument containing `{{state.x}}` could therefore copy another state field into the request. The
    builder's templates are now rendered once, and the arguments are inserted as values through `nodes.http_send`.
    A regression test covers it.
  - `arg_error` crashed on JSON Schema type lists (`["string", "null"]`), which MCP servers often send. Type lists
    now pass the check unvalidated.
  - Running until the Agent node paused after its entry step; it now pauses after `A/__exit`.
- **DEC-0063 text vs code:**
  - The hidden field is `agent:<id>`, not `__agent__<id>`. It follows the For each `loop:` cursors: it is declared
    only in the compiled state, never in the workflow's state schema, and it is left out of the run's final state
    and the trace deltas. The `agent:` prefix is reserved by the validator.
  - A provider without tool calling fails when the model step runs (`AGENT_TOOLS_UNSUPPORTED`), not at
    validation, because the validator never sees credentials.
  - DEC-0063 should be amended to say both (follow-up below).
- **The trace keeps the conversation in `input`.** The `node_finished.input` of agent steps holds the conversation,
  because time travel forks from `input` (`services/time_travel.py`). Past the 16k-character cap the step input is
  truncated and that checkpoint is not forkable. Progress checkpoints are not capped, so recovery is not affected.
  TASK-0118 should hide the `agent:` field in the trace view.
- **Streamed text in tool rounds.** Model text streamed in a round that also calls tools goes to the output field's
  `node_token` stream (the chat reply stream). Only the last round's text becomes the answer. TASK-0118 should
  treat earlier rounds as steps in the chat.
- **HTTP tool parity.** HTTP tools have method, URL, body and parameters, like the HTTP Tool node, but no headers or
  credential. REQ-0072 "Scope" names headers and a credential, but the HTTP Tool node has neither today. Adding
  them is a separate change for both.
- **Exports.** The Python and TypeScript exports still treat an Agent node as a pass-through. This is planned for
  TASK-0119 and recorded in the task's handoff notes.
- **Model-chosen built-in arguments.** Built-in tools get the model's arguments merged over the run state, so the
  model can set any state field the function reads. This is intended and documented in `register_tool`.
  `lookup_order` reads only `message`.

## Standards And Architecture Alignment

- Layers: the loop and the tools are in `engine/`; services only add the expansion in `RunService._expand`; MCP and
  knowledge bases are reached through `Ports`. No FastAPI or SQL in the engine and no migration. `tests/test_layers.py`
  passes.
- Errors: the one new code `AGENT_TOOLS_UNSUPPORTED` is in `CATALOG`, `docs/api-errors.md` and both locales (the vi
  wording uses the glossary term "công cụ"); `tests/test_api_envelope.py` passes.
- DRY: the HTTP request code is shared (`http_send`); provider calls stay in the registry (`invoke_tools`);
  expansion follows the subgraph pattern; the step budget follows `foreach.step_budget`.
- DEC-0063: four steps, one tool call per step, own ledger entry and idempotency key per step, routers in the
  compiler, `MAX_CALLS_PER_ROUND` 8, `max_rounds` 1-25 (default 5), last call without tools: as decided, with the
  two wording differences above.
