### Non-Blocking

- `_rollback` swallows a `restore_archive` error and still runs `up -d`. `restore_archive` refuses an archive whose recorded server version is newer than the CLI, and that refusal happens before it writes the old compose file. The following `up -d` then starts the new tag that `_restart` already wrote. Phase 1 `install` stamps `superstep.__version__`, and this command's backup records that version, so the archive from this run is not newer than the CLI that wrote it. The failure tests set `__version__` to `1.2.4` so restore accepts the `1.2.3` archive.
- REV-0138 still applies on the rollback path. `restore_archive` writes `.env`, `compose.yml`, and `secret.key` before the database load. A failed load still starts the stack. Upgrade then starts it again. The compose member is the pre-upgrade file, so the image tag is the previous one even when the database load failed.
- `wait_healthy` returns on any HTTP 200. Upgrade then requires `data.ok is True` on one `health()` call. It does not poll `ok`. The health route sets `ok` true on every 200, so the two checks move together. A later 200 with `ok` false rolls back on that single read.
- A failed `docker pull` or `docker load` happens after the backup and does not restore. The stack has not been restarted. The archive stays on disk.
