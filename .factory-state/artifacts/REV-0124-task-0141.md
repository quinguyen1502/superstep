## Findings

### Blocking

- None.

### Fixed During Review

- **Plan errors came out empty.** The first filter copied `code` and `message` from top-level error events, but
  `error_event()` puts them under `error`. The page would have seen an error with no code. The filter now keeps
  `error`, `errors` and `issues`, and the tests read `error.code`.
- **A visitor could have resumed any waiting run of the owner.** If the answer had trusted a `resume_run_id` from the
  client, a visitor could have sent another session's run id: `plan_resume` checks only that the run belongs to the
  owner, and every public run does. Now the answer always resumes the run of this session's last turn. That turn must
  be waiting for the visitor, and a `resume_run_id` the client sends must be that same run.

### Non-Blocking

- **Phase 1 is unchanged.** The studio path still goes through `input_for()` and `record()`, which now call
  `prepare()` and `write()`. The phase 1 chat tests pass without changes.
- **The sender of a public message is `visitor`** in the reply-once record when the chat is anonymous, and the user id
  when it is signed in. The run history's Chat badge shows it, and it does not reveal the visitor id.
- **The daily cap is counted before planning.** A message refused later, for example with `CHAT_RUN_WAITING`, still
  uses one message of the day. This is simpler, and only someone already sending messages can use up the cap.
- **Answers count towards the per-visitor and per-IP limits but not the daily cap**, so a Human question never makes a
  chat run out halfway through a conversation.
- **The all-in-one image.** The socket route is added before `mount_frontend`, so `SPAStaticFiles` never sees it. In
  Compose, nginx's `location /ws/` already sends it to the API.

## Checks

- Event filter: every streamed frame in labels mode has only `type`, `node`, `label`, `node_type`, `iteration` and
  `ts` on its node events. No frame has `state`, `input`, `metrics`, `trace_url`, `usage` or `superstep`.
- Layers: the router does the socket input and output. The service is free of FastAPI.
