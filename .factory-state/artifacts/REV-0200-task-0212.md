## Findings

- None. The deadline is set once per segment, right before the engine thread starts; the cancel listener, the

### Non-Blocking

- The first progress write is not bounded by the limit any more. It was not bounded before either (a slow write only

- The root of the 12.6 s write on the CI runner is not proven (no server timings in the artifacts, not reproducible
  locally). If it shows again it now costs time, not a failed run; a server-side timing log of slow writes would help.
- A resumed segment's `run_resumed` event still uses `t0`; only the deadline moved.
