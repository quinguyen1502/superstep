## Findings

### Blocking

- None. No acceptance criterion fails.

### Non-Blocking

- `session.call(..., phase2=True)` treats every HTTP 404 as `SERVER_TOO_OLD` before it reads the envelope. Name lookup uses the list, so zero matches is still `WORKFLOW_NOT_FOUND`. A direct GET of a missing id would be labeled `SERVER_TOO_OLD`.
- The version check and the later POST are two requests. A studio save between them can still be overwritten. The task asked for the check before the first POST.
- A directory that cannot be created is reported as `NOT_A_WORKFLOW`.

## Standards And Architecture Alignment

- The version field is computed in `WorkflowService` from `versions.latest`. It is not stored in the graph. `READ_ONLY` strips `version` and `updated` on save. No new server error code and no migration.
- The CLI does not import the backend. New codes live in the CLI catalogs only. The en and vi catalogs have the same keys.
- Commands are registered from `workflows.py`. Python stays on `from __future__ import annotations` and argparse.

## Design Alignment

- Pull, push, export, and import match DEC-0071 decision 4. There is no new screen.
