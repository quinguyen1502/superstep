### Non-Blocking

- **Only the Vietnamese label is checked in a browser.** The e2e browser runs in `vi-VN`; the English part of the
  test switches language on the template gallery and does not open a Human node. The en string is a plain value next
  to the other `approvals.*` strings, so the risk is low.
- **No automated guard for missing keys.** en and vi have identical keys (1399 each), but nothing in vitest fails
  when a component uses a key that neither locale has, which is how this bug reached `develop`. A scan of every
  literal `t('…')` key in `frontend/src` finds no other missing key today. Keys built at run time
  (`approvals.kind.${…}`) would need a separate check. A follow-up task could add such a test; not in this scope.
