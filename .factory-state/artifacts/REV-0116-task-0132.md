## Findings

### Blocking

### Non-Blocking

- **The English text did not change.** Every template in `MESSAGES` was copied from the f-string it replaces. The
  check-related suites (164 tests) assert on those strings and pass unchanged, and `Issue` is a `str`, so SDKs, MCP,
  exports and logs see the same lists.
- **One source for the English.** `en.json` `validation` is generated from `MESSAGES`, and
  `test_validation_messages.py` fails when they differ, when `vi.json` has other keys, or when the engine uses a code
  with no message. This follows the `errors.<CODE>` pattern of DEC-0010.
- **Subgraph names.** `subgraphs.readable()` rewrites node ids in the text, and now in the parameters too, so the
  Vietnamese text names `"Sub › Find"` as well. One small difference: for `NODE_NO_OUTGOING` inside a subgraph the
  English drops the `(label)` after the id, but the parameters keep the label, so the vi text shows both. This is
  harmless and only happens for nodes inside a subgraph.
- **Words in parameters stay English.** Lists joined with "or" (`types` = "integer or number"), technical keys
  (`steps_field`, `to`) and a code checker's own message (`NODE_PROBLEM`) are not translated. They are field types,
  setting names and compiler output, which the glossary keeps in English anyway.
- **For each field kinds.** The old messages put "list field", "item field" or "index field" into the text. Each
  combination now has its own code (nine in all), so the vi text can say "trường danh sách / phần tử / chỉ số". The
  combinations that cannot happen (an item field type, a list field reducer) have no code.
- **Run errors.** `error_event` adds `issues` only when at least one message has a code, so `RUN_FAILED` and node
  exceptions keep their old shape.

## Standards And Architecture Alignment

- Layers: `issues.py` is in `engine/` and imports nothing from services or the API. `WorkflowService.checked()` builds
  the response; the route only calls it. `tests/test_layers.py` passes.
- UI strings live in both locales with identical keys and placeholders. `locales.test.ts` (glossary, allowlist)
  passes. `validation.NODE_PROBLEM` is identical in both languages on purpose and is on the allowlist.
- No new API error codes, so `CATALOG` and `docs/api-errors.md` are unchanged. The API adds a field and changes none.

## Design Alignment
