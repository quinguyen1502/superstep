## Findings

### Blocking

- None.

### Fixed During Review

- **The export lost the tool's workflow.** The exporters sanitize every graph, which blanks `workflow_id` (a resource
  id for subgraphs, kept separately there), so the first export wrote "workflow not found". The graph now keeps a
  workflow tool's id, since that workflow is written into the same file.

### Non-Blocking

- **Approvals inside a child, in a test run and in an export.** A test run cannot answer a question inside a called
  workflow (its answers are keyed by the tested workflow's nodes), so the child is cancelled and the call fails. The
  template's refund case checks exactly that. In an export the child's interrupt pauses the parent graph, which is
  the "passed up" behaviour; the same-path test leaves that case out, and says why.
- **Saved and exported templates** carry the supervisor only. A user template saved from a supervisor, or the built-in
  exported as a file, has workflow tools with an empty workflow, which the validator reports so the user picks one.
  Helpers are a built-in feature.
- **TypeScript types.** The child graph's `invoke` gets the input cast to its own parameter type, and the final state is
  read as a record. This avoids a mismatch between the model's arguments (`Record<string, unknown>`) and the child's
  state type. `deno check` runs in CI. It could not run here, because deno is not installed on this machine and
  downloading it was not allowed in this session.
- **The steps comparison** in the same-path tests ignores `child_run_id` and `child_workflow_id`, which only the
  studio has. The parent's path and the rest of the state must match.
