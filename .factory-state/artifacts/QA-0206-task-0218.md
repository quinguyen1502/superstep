## Validation Scope

External JWT chat authentication on HTTP and socket v1, user isolation across session/turn/file/rating operations, token rotation/revocation, CORS, quotas, and anonymous/studio regression.

## Acceptance Criteria Coverage

- Valid token chats end to end: pass. `test_chat_user_tokens.py` covers HTTP start/history and typed socket streaming with bounded workflow identity/meta; last_used_at is updated. The Human text answer path authenticates only once for the socket.
- User A cannot read/rate/attach to user B or anonymous sessions: pass. Tests cover session/turn list, rating put/delete, upload/download/delete and socket message. Anonymous cookies cannot read app sessions; studio and app users remain isolated. The same external user can read history from another device and through either active key.
- alg none/wrong alg, audience/issuer, expired/future times, unknown kid, bad signature, revoked key: pass, with the specified catalogue codes on HTTP and socket. Additional cases cover lifetime cap, metadata type/size, malformed/base64/oversize JWTs, NaN, and malformed Unicode. 60 s expiration leeway is exercised.
- Rotation/revoke: pass. Second key reads the same user's existing session; revoking the first denies its next request immediately, with no cache. Disabling app access rejects token callers.
- Anonymous and studio access unchanged: pass in backend regression and browser tests. A legacy socket cannot bypass token-only cross-origin policy using a global CORS allowlist.
- Per-user messages/uploads and failed-auth IP limits: pass. Two users have independent message quotas, invalid verifications consume the existing message-IP quota, and all reads still use the per-IP read limit.
