### Non-Blocking

- The e2e rates down, sends the comment, and reloads. It does not click the pressed thumb a second time. The clear path is `onRate(id, null)` then `DELETE`, and the API test reads the rating back as null. A UI reload after that second click is still unshown.
- A waiting answer is excluded in `ChatThread` (`ok` and `error` only). The public e2e never opens a Human node, so that absence is from reading the component, not from the browser.

## Standards And Architecture Alignment

- shadcn `Button` and `Input`. Pressed thumb is `variant="secondary"` with `aria-pressed`. No hard-coded colour. `npm run lint` (oxlint and the UI class check) reported no new violations on 2026-10-27.
- The comment control is an `Input` with `maxLength` 1000, not a textarea.
- Locale keys match in en and vi. The public page calls `api()` and reloads the session after the rating.

## Design Alignment

The embed is the same `/c/{slug}` page, so it gets the same control. A second click removes the rating, which is the DEC-0070 interaction, rather than a typed-name delete dialog. That dialog is for deleting a named resource.
