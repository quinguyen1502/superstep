## Standards And Architecture Alignment

- Routers delegate to a service; SQLAlchemy persistence and the two-active-key lock live in a repository. The no-op trigger UPDATE serialises creators on SQLite and Postgres, including the empty-key case. No raw SQL in implementation code.
- Secrets are generated from 32 random bytes, encrypted with existing Fernet storage, returned only by creation with no-store, excluded from listings and audit details. Rotation creates a second key; revoke is an idempotent plain DELETE scoped to the chat.
- Owner/admin checks apply to listing and both mutations. Workflow deletion explicitly removes keys, including on SQLite without FK enforcement.
- UI checklist: shadcn controls and theme tokens, no hard-coded colours, exact-name ConfirmDeleteDialog, warning token for any-origin access, locale/glossary parity, one size per action row, keyboard-accessible checkboxes and labels. No new node config fields.
