### Non-Blocking

- `install.sh` was exercised with fake `uv`, `curl`, and `uname`. It was not run against PyPI, because `superstep==0.9.0` is not published until a `v*` tag.
- `image.yml` builds `superstep-api` and `superstep-web` in the publish job, which runs on a push to `develop` or a `v*` tag and does not run on a pull request. The pull-request job still builds the all-in-one image and runs `scripts/cli_smoke.py`.
- `cli.yml` runs the SDK unit tests on Python 3.12. `ci.yml` still runs them on 3.9 and 3.12.
- A second `install` checks the port before it checks `instance.json`. The smoke uses a free port so the refusal is `INSTALLED`.
- Restore assumes the API process user is named `studio`. `docker compose cp` writes as root, so restore runs `chown` before start. The entrypoint also chowns `/data` recursively; that line is in the image only after the next image build.
- The smoke isolates `HOME` and symlinks `~/.docker/cli-plugins` so Compose remains visible. It does not SSH to a second machine.
- Alembic still cannot roll a schema back. The forced health failure restores the previous tag and the database file.
