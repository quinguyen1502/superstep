## Standards And Architecture Alignment

- API dependencies/middleware handle transport; the service/verifier handles authentication/domain decisions; SQLAlchemy repositories perform reads/writes. `tests/test_layers.py` passes. Existing 0051 columns are sufficient; no schema change.
- Only HS256 is accepted; known key, signature, issuer, audience, numeric iat/exp/nbf, 60 s skew and one-hour lifetime cap are enforced. JSON size, duplicate claims, non-finite values and malformed Unicode are bounded/rejected with catalogue codes. Encrypted secrets never enter identity objects, response metadata, logs or workflows.
- A validated app token wins over an anonymous cookie. App, anonymous and studio sessions have disjoint ownership checks, including file/rating operations. Both active rotation keys share the same (trigger, external user) scope. Revocation is rechecked by a conditional last-used write.
- CORS is restricted to the public-chat paths and requires a verified app token for actual cross-origin reads/writes. Preflight only permits the app header/method set; no credentialed CORS is emitted. Allowed-origin checks run before expired/revoked errors are exposed to a browser for refresh. Studio/global CORS settings cannot bypass the chat policy.
- Legacy sockets remain same-origin; v1 can authenticate through the first frame or token query fallback. A socket authenticates once before its message; expiry does not reauthenticate/cut its running stream. The existing query-token log redaction remains in place.
- Proxy Host retains the external port; WebSocket forwarding includes protocol and peer IP. Without this, strict origin checks would break Compose deployments on non-default ports.
- New errors are present in CATALOG, api-errors and both locales. No new visual UI/components or deletion interaction.
