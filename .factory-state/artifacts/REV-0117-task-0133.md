### Fixed During Review

- **A non-list `inputs` gave one error per character.** `check()` iterated `t.get("inputs") or []`, so the string
  `"message"` gave seven "unknown field" errors on top of `AGENT_TOOL_INPUTS`. It now reads lists only; the validator
  reports the wrong shape once. A test covers it.
- **A snapshot sent with the workflow could be run.** A client (or an editor's saved JSON) could put `snapshot` on a
  tool, and TASK-0134 would run it. `snapshot()` now drops every `snapshot` and `version` that came with the workflow,
  on Agent nodes and on already expanded steps, before it makes its own. A test covers both.

### Non-Blocking

- **One check for both kinds of reference.** `check()` walks subgraphs and workflow tools in one pass, so a cycle
  closed by either kind is found (A calls B as a tool, B embeds A as a subgraph), and the depth limit counts both, as
  REQ-0073 asks. The walk may visit a child twice when two tools call it; depth is at most 5, so this is cheap.
- **Checkpoint size.** The child snapshot is copied onto the tool step only. The entry, model and exit steps keep the
  child's state fields, which the model step needs for the parameter types. With nesting, the tool step's snapshot
  holds its own children, so the size grows with the chain, bounded by the depth limit and `workflow_max` per stored
  workflow.
- **Parameters are required.** Every input field the builder picks is required in the schema the model sees. A
  builder who wants an optional input leaves it out of `inputs`; the child's default applies.
- **Deleting a child.** `dependents()` now counts workflow tools, so deleting a workflow used as a tool is refused with
  `WORKFLOW_IN_USE` unless forced, as for subgraphs. `children_changed` lists tool children too, once each.
- **Exports.** `WorkflowService.export` calls `check()`, so an export now also reports a broken workflow tool. Writing
  workflow tools into the exports is TASK-0137.
