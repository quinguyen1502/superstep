## Findings

### Blocking

- None.

### Fixed During Review

- **The page was always light.** The studio's theme defaults to light unless the user picks one. A visitor has never
  picked one, so the page ignored their dark system setting (seen in the en screenshot). `useSystemTheme()` now
  follows `prefers-color-scheme` when no theme was chosen and no `?theme=` is set. It stores nothing.
- **Suggestion buttons were squashed.** `size="sm"` with `h-auto` removed the vertical padding. They now use the
  default size with `min-h-9 py-2`, so a long suggestion wraps; this is marked `ui-class-ok`.
- **Visitor chats were out of reach in the narrow panel.** The compact Chat tab has no sidebar. Visitor chats now
  appear as a "Visitors" group in its session picker.
- **The `useChatRun` dependencies.** A first version worked around the hook's lint rule. The endpoint is now memoised by
  each caller and is a real dependency.

### Non-Blocking

- **The page makes no studio calls.** It does not call `/api/me` or the workflow list. `CommandPalette` stays mounted
  but opens only for signed-in users, as before.
- **signed_in redirect.** The page reads `signed_in` from `GET /api/public/chat/{slug}` and sends the visitor to
  `/login?next=/c/{slug}`. The login page already honours `next`.
- **"New chat"** clears the selection, and the next message creates the session, as the Chat tab does. No empty
  sessions are made.
- **Builders see visitor chats with every step**, through `ChatThread` in `full` mode. The composer is hidden.

## UI Checklist (`docs/ui-conventions.md`)

- shadcn components only: Empty, Select, Tabs, InputGroup, Textarea, Separator and Button. Theme tokens only;
  `lint:ui --strict` reports no hits.
- Every string is in en and vi with the same keys. The glossary has rows for public page, page address, intro,
  suggested message and Visitors.
- Light, dark and phone (390 px) screenshots are checked: the empty page with intro and suggestion, an answered chat,
  the phone layout, the Visitors view, and the "not available" page.
- Focus and labels: the slug input has a `/c/` addon and `aria-invalid` on slug errors. Each suggestion input has an
  aria-label with its number, and the icon buttons have aria-labels.
