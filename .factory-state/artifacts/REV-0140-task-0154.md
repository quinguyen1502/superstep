## Findings

### Blocking

- None.

### Non-Blocking

- Optional `--password` is placed on the `docker compose exec` argument list. A generated password is not. The process list on the host can show a password the operator typed. The CLI prints the process stdout once and does not write it to `instance.json` or `cli.json`.
- `set_password` records `password_changed`, so older JWTs stop working. The service does not clear the login throttle and does not delete open password-reset links. An email that is still inside the lock window can fail sign-in after the hash changes. An unused reset link can still set another password.
- `uninstall --purge` runs `docker compose down -v`, then `docker volume rm` for each name in `instance.json`. A missing volume is ignored. `down -v` does not remove an external volume; the following `volume rm` does. Backup archives whose default directory is the instance directory are deleted with that directory.
- `admin_cmd` runs `Database.migrate()` before the service. The call is idempotent and uses the same migration lock as API startup. The published image does not contain this module until TASK-0156. Tests use SQLite and a fake exec.
- Shell completion lists the top-level commands `admin` and `uninstall`. It does not list `create`, `reset-password`, or `list`.

There is no confirm field on a DELETE.
