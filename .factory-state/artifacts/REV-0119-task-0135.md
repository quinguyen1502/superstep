## Findings

### Blocking

- None.

### Fixed During Review

- **The trace summary said "Waiting for a human"** for a run waiting for its child (seen in the first screenshots).
  It now reads "Waiting for another workflow" (`trace.waitingChild`).

### Non-Blocking

- **Names follow access.** `links()` names a parent or child workflow only for people who may open it.
  `test_runs_link_parents_and_children` checks it with a second user. The inbox already lists only steps the user
  may answer, and a child runs as the parent's owner, so the chain there is the owner's own workflows or ones shared
  with them.
- **Polling.** The parent goes on in the worker, not on the studio's socket, so the run panel asks for the history
  every 2 s while it shows a child wait, and stops when the run moves on or the panel closes. This only happens while
  such a run is open.
- **The icon.** The summary keeps the Human hand icon for any `waiting` status. A different icon was not worth a new
  token; the text says which wait it is.
- **The inbox query** reads the run once per row to know whether it is a child. The inbox is short (open steps only),
  so this was kept simple.
