### Non-Blocking

- Lockout: sign-in and password change share one check (`_check_password`), so a wrong current password counts toward the same per-e-mail lock, and a lock refuses even the right password. The caller's session is not ended by a lock.
- Sessions: the change sets `password_changed`, so older tokens fail with `AUTH_TOKEN_EXPIRED`; the response is a new session and sets the cookie. Tokens carry whole seconds, so a token issued in the same second as the change still works (same as the reset link of TASK-0045).
- Open reset links of the account are deleted on change, so a link made earlier cannot undo it.
- A new password equal to the current one is refused (`AUTH_PASSWORD_SAME`); the password rules are the shared `password_problem`.
- `login` keeps its order of checks except that a successful password on a deactivated account now clears the failure counter before `AUTH_ACCOUNT_DISABLED`. Harmless: the account still cannot sign in.
- The demo account can change its password like any other; production does not create it.
