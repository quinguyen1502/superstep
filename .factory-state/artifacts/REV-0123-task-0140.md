## Findings

### Blocking

- None.

### Fixed During Review

- **Old chats would have failed to save.** A chat made before this change has the slug `wid.lower()`. Checking the slug
  on every save could refuse a builder who only changed the step mode. The slug is now checked only when it changes or
  when the chat is published, and publishing always needs a valid slug.
- **The list answer had two shapes.** `GET .../sessions` would have returned a list from a cookie and an object from the
  widget header. It now always returns `{sessions}`, and adds `visitor_token` only for the widget.

### Non-Blocking

- **The cookie lives for 400 days**, the most that browsers keep. Each session is still deleted by `retention_days`, so
  an old cookie only finds sessions that are still kept.
- **Tokens are bound to the slug**, as DEC-0067 says. Changing the slug starts every visitor afresh, and their old
  sessions stay until retention deletes them.
- **Cross-site POST.** With `SameSite=None` over HTTPS, another site could make a visitor's browser create an empty
  session. That gives no data away, and messages go over the socket, where TASK-0141 checks the `Origin`.
- **The page title** falls back to the workflow's name when the builder sets none. The name is chosen by the builder
  and is shown to visitors anyway, so this reveals nothing else.
- **No migration.** `uq_workflow_chat_triggers_command` already makes the web slug unique (`channel_id`, `place` and
  `command` are `web`, `web` and the slug). `CHAT_SLUG_TAKEN` reports it before the database would refuse it.
- **The UI still shows `anonymous` and `signed_in` as "later".** TASK-0142 changes `lib/chat.ts` and the settings
  dialog.

## Checks

- DEC-0009: the router reads cookies and headers and sets the cookie. The service has no FastAPI import.
  `tests/test_layers.py` passes.
- The envelope and the central handlers are used, with no try/except per route except `maybe_user()`, which turns "not
  signed in" into None. `tests/test_api_envelope.py` passes.
- Every repository call in `PublicChatService` uses the trigger, and nothing uses the visitor's rights.

## Decision

Approved for QA.
