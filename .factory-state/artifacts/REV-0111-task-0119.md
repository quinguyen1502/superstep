## Findings

### Blocking

- None. No blocking findings.

### Non-Blocking

- **What "called" means.** The check passes `called: true` when the call ran: it returned a result, or the tool itself
  failed (`agents.FAILED`). A call that was refused (too many in a round), rejected by an approver, or had an unknown
  tool or invalid arguments did not run. This is what a test author asks ("did the refund go out?"). The engine
  shares the failure marker with the check, so the two cannot drift apart.
- **A built-in example tool instead of an HTTP tool.** The task's example template had a `send_refund` HTTP tool.
  The template uses the new built-in `request_refund` instead, which pays nothing and returns a fixed text (en, vi).
  An HTTP tool would make the approved test case and the export's same-path check depend on the network.
  `request_refund` also shows up in the Tool node's function list; that is harmless, like `lookup_order`.
- **The knowledge base tool.** The template's policy search needs a knowledge base, as `builtin-rag` does: the only
  validator error left is "choose a knowledge base". The pytest of the template's cases picks one; the e2e drops the
  tool, since no case calls it.
- **Python export and the studio.**
  - The exported mock (`mock_agent`) and the argument check (`check_arguments`) are compared with the engine's own
    in `test_helpers_match_the_engine`.
  - The same-path check covers the template's three cases and an agent that uses all four tool sources, approved
    and rejected.
  - Tool call durations (`ms`) differ between two runs, so the steps fields are compared without them.
  - With `LLM_PROVIDER` set, `call_agent` uses LangChain `bind_tools`, as the studio's OpenAI path does. This is not
    run in CI, because it needs a provider key.
- **TypeScript.** Agent nodes, also inside a subgraph child, are refused with a code. The Code tab already shows
  translated API errors, so it needed no change.
- **Merge of #145.** The Tests panel e2e needs the Agent node on the canvas (TASK-0118). Merge order: #144, #146,
  #145, then this PR.
